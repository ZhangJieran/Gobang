# Design

## Context

本项目为全新的五子棋人机对战游戏，采用 React + TypeScript 纯前端实现，无后端、无数据库。游戏核心由棋盘渲染、规则引擎和 AI 对手三部分组成。

## Goals / Non-Goals

**Goals:**

- 提供完整可玩的五子棋人机对战体验
- 实现标准 15x15 棋盘及专业禁手规则
- AI 对手具备基本棋力，能识别威胁并进攻
- 界面采用经典木质风格，交互流畅自然

**Non-Goals:**

- 不实现在线多人对战
- 不实现多个 AI 难度等级
- 不实现禁手之外的其他专业规则（如五手两打、交换等）
- 不实现棋谱保存/加载功能

## Decisions

### 1. 纯前端架构

**决策**：使用 React + TypeScript + Vite 构建单页应用，所有逻辑（含 AI）在浏览器端运行。

**理由**：人机对战无需服务端通信，纯前端可简化部署、降低延迟。AI 采用启发式评估，计算量在浏览器可承受范围内。

**备选方案**：后端 Python 运行 AI —— 增加网络延迟和运维成本，对于单一难度的启发式 AI 无必要。

### 2. 棋盘数据结构

**决策**：使用二维数组 `number[][]` 表示棋盘，0=空、1=黑、2=白，坐标为 `[row, col]`。

**理由**：15x15 棋盘规模小，二维数组直观且便于棋型扫描和胜负判定。

### 3. 胜负判定算法

**决策**：落子后仅在该子的四个方向（横、竖、两斜）扫描连续同色棋子数，达到 5 即胜。

**理由**：只需检查最后落子周围，无需全棋盘扫描，效率高。

### 4. 禁手检测算法

**决策**：对黑棋每个候选空位，模拟落子后检测是否形成三三、四四或长连。

**理由**：禁手判定基于该步落子后的棋型变化，模拟落子后扫描四个方向的棋型即可准确判定。棋型识别需区分活三/眠三、活四/冲四等。

### 5. AI 启发式评估

**决策**：对每个空位评分，综合考虑进攻分（己方棋型）和防守分（对方棋型），选择总分最高的位置。

**理由**：启发式评估无需搜索多步，计算快且棋力可接受。评分基于棋型（连五、活四、冲四、活三、眠三等）的权重。

**备选方案**：Minimax 搜索 —— 计算量大，浏览器端可能卡顿，且单一难度下启发式已足够。

### 6. 状态管理

**决策**：使用 React `useReducer` 管理游戏状态（棋盘、当前回合、游戏状态、落子历史）。

**理由**：游戏状态转换清晰（落子、悔棋、重开），useReducer 比多个 useState 更易维护和调试。

## Risks / Trade-offs

- **禁手检测复杂度**：三三/四四禁手需精确识别棋型，边界情况多。→ 缓解：模块化棋型识别函数，逐一覆盖活三/眠三/活四/冲四等定义。
- **AI 棋力不可控**：启发式评估的权重调参影响 AI 强度。→ 缓解：采用经典棋型权重表，先保证能识别基本威胁。
- **AI 计算阻塞 UI**：评估 15x15 所有空位可能造成短暂卡顿。→ 缓解：只评估候选点（已有棋子周围两格内），缩小搜索范围；配合 setTimeout 异步执行避免阻塞。

## Migration Plan

全新项目，无迁移需求。构建后可直接部署为静态站点。
